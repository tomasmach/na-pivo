1:1 přenos repozitáře na Nobara PC

návrh17. 7. 2026zdroj: macOS → cíl: nobara-pc:~/Code/na-pivo

Doporučený postup je bezpečný přenos přes rsync a SSH. Nejdřív se pouze přečte stav cíle, potom se zkopíruje celý pracovní adresář včetně .git, envů, ignorovaných i necommitnutých souborů; nakonec se porovná inventář a kontrolní součty citlivých souborů bez výpisu jejich obsahu.

0 z 6 kroků hotovo

Cílový adresář se nebude mazat ani přepisovat, dokud nebude ověřeno, že je prázdný, neexistuje, nebo že jeho nahrazení uživatel výslovně schválil.

Rozsah

Cíle

  • celý Git checkout včetně historie a pracovního stromu;
  • .env, .env.local, backend/.env a lokální Xcode env;
  • ignorované a necommitnuté soubory pro skutečně 1:1 kopii;
  • zachování oprávnění, časů a symlinků, kde to platformy dovolí.

Ne-cíle

  • produkční deploy nebo změna vzdáleného Git repozitáře;
  • instalace systémových balíčků na Nobaru;
  • spuštění aplikace před ověřením kopie;
  • výpis hodnot secretů do terminálu či plánu.

Aktuálně zjištěné citlivé/velké položky zahrnují také AuthKey.p8, google-service-account.json, backend/db.sqlite3, backend/media/, node_modules/, ios/, android/, build artefakty a lokální cache. Přesná varianta „1:1“ je zahrne.

Tok dat a bezpečnostní brány

Provedení

1. Ověřit SSH dostupnost

Vyzkoušet alias nobara-pc; při nedostupném mDNS použít Tailscale alias nobara-pc-ts.

ssh -o BatchMode=yes -o ConnectTimeout=7 nobara-pc 'printf ready'

2. Přečíst stav cílové složky

Ověřit domovský adresář, volné místo a zda ~/Code/na-pivo už existuje.

Pokud existuje a obsahuje neznámá data, přenos se zastaví. Bez schválení se nepoužije --delete ani destruktivní nahrazení.

3. Změřit zdroj a udělat bezpečný dry-run

Zjistit velikost adresáře a spustit rsync --dry-run, aby byl znám rozsah přenosu.

Obsah envů ani klíčů se nevypisuje. Kontrolují se pouze názvy, velikosti, oprávnění a později hash.

4. Přenést kompletní checkout

Použít archivní režim, kompresi a průběžně obnovitelný přenos.

rsync -aHz --partial --info=progress2 /Users/tomasmach/Code/na-pivo/ nobara-pc:~/Code/na-pivo/

5. Ověřit shodu bez úniku secretů

Porovnat Git HEAD/status, počet souborů a kontrolní součty vybraných envů a klíčů.

Kvůli rozdílům macOS/Linux se nevyžaduje shoda metadat, která Linux neumí převzít; rozhodující je obsah souborů, symlinky a pracovní strom.

6. Ověřit použitelnost na Nobaře

Nejdřív jen zkontrolovat dostupnost Node/Bun, Python/UV, Dockeru a Git LFS. Instalace nebo npm run dev je samostatný krok.

Přenesené node_modules, .venv, iOS buildy a macOS binárky mohou být obsahově 1:1, ale na Linuxu nemusí být spustitelné. Zdroj zůstane přesný; runtime závislosti se případně obnoví nativně.

Kompletní pracovní adresář

Přenese se vše pod kořenem projektu: Git data, envy, databáze, média, klíče, cache, buildy i závislosti. Je to jediná varianta odpovídající doslovnému „1:1“.

Reprodukovatelný Linux checkout

Přenesou se zdroje, Git data, envy, lokální databáze a média, ale vynechají se node_modules, .venv, platformní buildy a cache. Rychlejší a praktičtější, ale nejde o přesnou kopii.

Čistý clone

Nejmenší přenos, ale chybí necommitnutý plán, ignorované soubory, lokální data a secret konfigurace. Pro toto zadání nevhodné.

Rizika a pojistky

Existující cílová data

Nejdřív pouze inventář. Žádné rm, --delete ani overwrite konfliktního checkoutu bez výslovného potvrzení.

Citlivé soubory

SSH přenos je šifrovaný. Hodnoty envů a klíčů se neukazují; ověření používá SHA-256.

Platformně závislé artefakty

macOS/iOS binárky a virtuální prostředí mohou být na Nobaře nepoužitelné. Kopie může být 1:1, ale pro běh bude potřeba nativní reinstall.

Velikost přenosu

node_modules, buildy, média a cache mohou přenos výrazně zvětšit. Dry-run a měření proběhnou před ostrým kopírováním.
